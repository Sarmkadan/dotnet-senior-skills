# CLAUDE.md

Senior-level .NET code-review rules (27 skills) packaged for coding agents: Claude Code, Cursor, GitHub Copilot, Windsurf, Cline, and generic AGENTS.md.

## Build

No compiled artifact. "Build" means regenerating the derived rule formats from the canonical skills:

```sh
python3 generate_agent_formats.py   # regenerates AGENTS.md, .windsurfrules/*.md, .clinerules/*.clinerules
./scripts/gen-readme-table.sh       # regenerates the skills table in README.md (CI fails if stale)
```

Both scripts must be run from the repo root (they use relative `skills/` paths).

## Test / Validate

```sh
python3 validate_skills.py                       # frontmatter schema + compiles every ```csharp block (needs dotnet SDK 8)
python3 validate_rule_consistency.py [--verbose] # drift check: skills vs .cursor/rules vs .github/copilot-instructions.md
python3 reconcile_rules.py check|report|checklist
./test_install.sh                                # install.sh harness (idempotency, spaces in paths, existing files)
./test_readme_generator.sh                       # gen-readme-table.sh harness
```

CI (`.github/workflows/validate.yml`, on push/PR to `main`): validates frontmatter, builds each C# sample as a net8.0 project with EF Core 8, and checks the README table is up to date.

## Lint / Format

None configured. Python scripts are plain stdlib (no ruff/black). Shell scripts use `set -euo pipefail`.

## Key directories and entry points

- `skills/<name>/SKILL.md` - canonical source of truth, one directory per skill, frontmatter `name` + `description` (optional `version`, `source-commit`).
- `.cursor/rules/*.mdc` - Cursor format, maintained by hand (mirrors SKILL.md content).
- `.github/copilot-instructions.md` - condensed Copilot format, maintained by hand.
- `AGENTS.md`, `.windsurfrules/`, `.clinerules/` - generated by `generate_agent_formats.py`; do not edit directly.
- `install.sh` - installs into a target project (`--tools`, `--only`, `--skip`, `--force`, `--dry-run`, `--uninstall`, `--upgrade`).
- `scripts/gen-readme-table.sh` - README table generator.
- `VERSION` - semver of the rule set.
- `RULE_CONSISTENCY_README.md` - how the three-format drift system works.

## Conventions

- Skill names: lowercase, digits and hyphens only (`^[a-z0-9-]+$`); directory name == frontmatter `name`.
- Category is the first hyphen segment of the skill name (`ef`, `async`, `di`, `http`, ...); `install.sh --only/--skip` and `generate_agent_formats.py` group by it.
- Every C# sample must compile under net8.0 with EF Core 8, or start with the exact line `// non-compiling: illustrative` to opt out.
- Rules are written as concrete thresholds with before/after C# ("one Include is fine; two is a comment; three is a rejection"), not abstract principles.
- Frontmatter `description` must be a single line (the README generator and CI read only that line).
- When a SKILL.md changes: update the matching `.cursor/rules/*.mdc` and Copilot section, then run `generate_agent_formats.py` and `gen-readme-table.sh`, then `validate_rule_consistency.py`.
- Commits: conventional commits, lowercase, no AI mentions. Do not add NuGet packages or touch project files in samples.
